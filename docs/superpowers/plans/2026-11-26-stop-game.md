# Stop — Local Multiplayer iPhone Game Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A polished, well-tested iPhone app for playing Stop with nearby friends over the local network, with no server, that survives app interruptions without losing answers or desyncing.

**Architecture:** A local Swift package `StopKit` holds all logic in four library targets: `StopCore` (a pure game engine: models, rules, and a host state machine), `StopNetworking` (a `Transport` abstraction with a Network.framework implementation and an in-memory fault-injecting fake), `StopSession` (host/client coordinators covering wire protocol, heartbeat, presence, acknowledgements, reconnection, snapshot resync and persistence) and `StopSimulation` (bot players, used by the user-facing **Practice with bots** mode, the tests and the UI-test mock mode). The SwiftUI app target depends only on the `GameClient` protocol and renders the host-authoritative `GameState`.

**Tech Stack:** Swift 6.4 (strict concurrency), SwiftUI + Observation, Network.framework (Bonjour + peer-to-peer Wi-Fi + TCP), Swift Testing, XCTest/XCUITest for UI tests, String Catalogs. No third-party dependencies.

**Spec:** `docs/superpowers/specs/2026-11-26-stop-game-design.md` (read it before starting any task)

## Global Constraints

- iOS 27.0 minimum deployment target, iPhone only, portrait only. The package also declares macOS 27 so `swift test` runs on the Mac host.
- Swift 6 language mode, strict concurrency complete; no warnings in our code.
- No third-party runtime or build dependencies (no XcodeGen, no SPM packages).
- Bundle ID `com.gchapiewski.stopapp`; UI test bundle `com.gchapiewski.stopapp.uitests`. Display name placeholder: `Stop!` (owner will rename later).
- Bonjour service type `_stopgame._tcp`. `NSBonjourServices = ["_stopgame._tcp"]`. `NSLocalNetworkUsageDescription` is localized (en + pt-BR).
- Wire `protocolVersion = 1`.
- Letters: all 26 letters A–Z, with no repeats within a game until all 26 are used, then reset.
- Scores: 10 / 5 / 0 only. A blank answer (empty after trimming whitespace) is fixed at 0.
- Timing: heartbeat 1 s; peer marked away after 3 s of silence; letter reveal 2 ticks then a 3-2-1 countdown (1 s ticks); scoring auto-advances 1 tick after a category completes; "host may be gone" after 120 s; reconnect backoff 0.25 s, 0.5 s, 1 s, then every 2 s.
- UI languages: English (`en`, development language) and Brazilian Portuguese (`pt-BR`). Every user-facing string lives in `Localizable.xcstrings` with both translations.
- Typing never touches the network or the shared observable game model.
- Commit at the end of every task **and push** (`git push`). The remote `origin` is configured and `main` tracks it.
- Simulator for app builds/tests: `iPhone 17` (`tools/test.sh` picks it, falling back to the first available iPhone).

## Review Focus

1. **Duplicate display names** (two players both called "Ana"): the engine keys everything by UUID; the UI disambiguates with a suffix ("Ana 2") wherever names are shown. Test in Task 4 and Task 14.
2. **Whitespace-only answers** count as blank: STOP stays disabled, the score is forced to 0, and scoring for that player auto-completes. Test in Task 5 and Task 6.
3. **Racing stops:** a STOP that arrives after the round already locked (several players tap at once) is rejected with `wrongPhase`. The client acknowledges the rejection and never retries it forever, and it doesn't count as an extra stop. Test in Task 5 and Task 11.
4. **App killed mid-writing, then relaunched:** the draft for that game and round is restored into the fields, and the client rejoins automatically. Test in Task 11 and Task 17.
5. **Drafts must not leak across rounds:** a client reconnecting after the host moved to the next round never submits or shows the previous round's draft. Drafts are keyed by `(gameID, round)` and cleared when a game ends. Test in Task 11.

```swift
public enum GameEngine {
  public static func newGame(gameID: UUID, hostID: PlayerID, hostName: String, settings: GameSettings, language: GameLanguage) throws(GameError) -> GameState  // version 0, phase .lobby, host present
  public static func apply(_ intent: Intent, from sender: PlayerID, to state: inout GameState, using rng: inout some RandomNumberGenerator) throws(GameError)
  public static func tick(_ state: inout GameState) -> Bool                       // Task 5/6
  public static func setPresence(_ presence: Presence, for player: PlayerID, in state: inout GameState) -> Bool  // Task 6
}
```
Every successful state change increments `version` by exactly 1. A failed intent leaves the state byte-for-byte unchanged (apply to a copy and assign on success). Idempotent no-ops (such as re-joining with the same name while present) don't bump the version.

Rules for this task:
- `join(name)`: unknown ID in `.lobby` → append present player (trimmed name; empty → `GameError.invalidSettings`). Unknown ID outside the lobby → `gameClosed`. A known ID in any phase → presence `.present` and name updated. Rejoining left/removed players aren't added to the current round's participants.
- `leave`: sender presence `.left`. The host can't leave (`notHost`; the host ends the game instead).
- `removePlayer(id)`: host only, any phase, can't target the host → presence `.removed`.
- `updateSettings`: host, lobby, validated.
- `updateRoundSettings`: host, lobby or roundResults; `stopsRequired >= 1`.
- `startGame`: host, lobby, ≥ 2 present players (`notEnoughPlayers`). Picks a letter, appends `Round(number: 1, participants: present players in join order)` and sets phase `.revealing(ticksRemaining: 2)`.
- Any non-host intent from an ID not in `players` (except `join`) → `unknownPlayer`.

### Task 5: Game engine — reveal, countdown, stops, collecting

**Files:** Create `Sources/StopCore/GameEngine+Round.swift`; Modify `GameEngine.swift`; Test `Tests/StopCoreTests/EngineRoundTests.swift`

**Interfaces:**
- Produces (behavior of `tick`, `apply`):
  - `tick`: `.revealing(2)→.revealing(1)→.countdown(3)→(2)→(1)→.writing`. Returns `true` and bumps the version when it changes anything.
  - `stop(answers)`: phase `.writing` else `wrongPhase`; sender is a participant else `notParticipant`; not already stopped else `alreadyStopped`; `answers.count == categories.count` else `answersIncomplete`; every answer non-blank else `answersIncomplete`.
